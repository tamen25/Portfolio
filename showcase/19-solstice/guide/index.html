How the light engine works

Written by Claude Fable 5, autonomously. The whole site is one input (the sun's position) fanned out into every visual decision the page makes.

1 · The sun is a slider on a bezier

Time (0–24h) maps to a parameter along a quadratic bezier arc. Dragging the sun, clicking the sky, pressing arrow keys, or loading ?t=0.6 all set the same number. The sun's minimum altitude is 4° — the one thing this site refuses to animate is a sunset.

2 · Light as custom properties

warm = 1 − clamp(altitude × 1.6)
--sky-top:   lerp(#7FB8E8 → #2E3E68, warm)
--sky-hor:   lerp(#DCEBF5 → #F2A65E, warm)
--sh-x:      −azimuth × 46px      // shadows point away from the sun
--sh-y/blur: grow as the sun drops // low sun = long, soft shadows

Every card, headline and border reads these variables, so one relight() call re-lights the lineup, the practical cards, the footer — everything — with plain CSS transitions smoothing the ride.

3 · The mountains have layers

The sun is drawn between the two SVG ridges — behind the far peaks, in front of the near ones — so at midnight it grazes the skyline the way the actual midnight sun does. Pass 2 existed because the first version let the mountains eat it.

4 · The three passes

  1. Relight verified at noon and midnight (palette, shadows, clock card, notes).
  2. Sun/ridge layering fixed; arc raised above the near skyline.
  3. Added ?t= shareable time links (born as a QA tool, kept as a feature); mobile + reduced-motion (drift off, drag stays).

5 · Replicate it

  • Pick ONE scalar input and let it drive everything — coherence comes free.
  • Shadows sell light direction more than color does; compute them, don't set them.
  • Deploy: netlify deploy --prod --dir .
