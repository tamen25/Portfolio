HOW THIS SITE WAS MADE

Written by Claude Fable 5, which designed and built this site autonomously — concept, code, copy, and the iteration passes below. This page exists so you can do the same.

1 · CONCEPT FIRST, AESTHETIC SECOND

The brief I gave myself: a page that is an instrument, not a page about one. A live procedural terrain the visitor can reseed means the hero is genuinely infinite — no two visitors ever see the same world. Every design decision followed from the instrument fiction: HUD corners, leader-line callouts, an elevation histogram, a cross-section profile. Structure is information: every gauge on screen reads real data from the current terrain.

2 · REFERENCE SWEEP

I searched Pinterest for sci-fi HUD interface design with a headless browser, pulled ~20 pins, and studied six at high resolution. What I kept: near-black grounds with white hairline linework, tiny uppercase labels with index numbers, dot-matrix data rasters, and leader-line callouts annotating a 3D object. What I rejected: the teal hexagon hologram look, which reads as a video-game asset pack. I also swapped the reference's red accent for phosphor amber — the color of radar scopes and oscilloscopes — so the palette wouldn't fall into the "dark site + acid accent" AI cliché. No downloaded image ships on this site: every pixel of the terrain is computed.

3 · THE TECHNIQUE

  1. Heightfield on the CPU. A seeded PRNG (mulberry32) shuffles a simplex permutation table, six octaves of fractal noise get domain-warped so ridges bend organically, and a ridged component (1−|fbm|) adds mountain character. 256×256 floats.
  2. Displacement on the GPU. The field uploads as a DataTexture; a vertex shader lifts 65k vertices. Sea level and relief are uniforms — the sliders never rebuild geometry.
  3. Contours in the fragment shader. The signature trick: 
    float cline(float h, float st){
  float f = abs(fract(h/st - .5) - .5) * st;   // distance to nearest contour
  float w = fwidth(h) * 1.3;                    // screen-space anti-aliasing
  return 1. - smoothstep(0., w, f);
}
    Minor lines every 0.02, majors every 0.10, shoreline ink where altitude crosses sea level.
  4. Callouts from real data. The CPU copy of the field knows the true apex and nadir; each frame their grid positions are projected to screen space and DOM labels + SVG leader lines follow.

4 · THE THREE ITERATION PASSES

PASS 1 — FRAMING & FURNITURE

First render had dead space around a spiky gold pile. Pulled the camera in, broadened the landforms, raised the default sea so shorelines — the most beautiful output of the contour shader — actually appear. Fixed a 18px gap where leader lines didn't reach their labels. Added the PROFILE A—A′ cross-section (a data-true strip through the apex row).

PASS 2 — DATA HONESTY

Noticed the apex callout always read ALT 1.000 — per-seed normalization made the star gauge meaningless. Switched to a fixed global scale so every world has an honest apex. Made the three Survey Log worlds clickable (their hex seeds load deterministically), then rewrote the log copy from screenshots of the real worlds so every described feature exists.

PASS 3 — SMALL SCREENS & TOUCH

Narrow aspect ratios clipped the terrain — camera radius now scales with aspect. Log rows re-stack for one column, and the LOAD affordance shows permanently on touch devices where hover doesn't exist. Reduced motion: auto-drift and the scan sweep stop; the instrument renders statically and still works.

5 · REPLICATE IT

  • No build step: one HTML file, one CSS file, one JS module, Three.js via CDN import map.
  • Generate data where the CPU can see it; render it where the GPU can lift it.
  • Make every decoration read real data — a histogram that isn't fake is worth ten that are.
  • Screenshot your own work and critique it like a stranger. Three passes minimum.
  • Deploy: netlify deploy --prod --dir . — static files, no build minutes.
