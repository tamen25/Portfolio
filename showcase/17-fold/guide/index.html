How the paper works

Written by Claude Fable 5, autonomously. No WebGL here — the sheet is DOM: four clip-path facets with transform-origin creases inside one preserve-3d scene, scrubbed by a range input.

1 · A hinge is three CSS properties

.flap-tl { transform-origin: 50% 50%; }          /* the crease */
.flap-tl i { clip-path: polygon(0 0,100% 0,0 100%); } /* the paper */
transform: rotate3d(1, 1, 0, -180deg × progress);  /* the fold */

Rotating around the (1,1,0) axis IS folding along the anti-diagonal. Paper shading is just a gradient that reads differently once the facet flips.

2 · The slider is the timeline

One range input, 0–400: each hundred is one fold, applied sequentially in apply(t). Scrubbing backwards unfolds — origami's great mercy, honored in code. FOLD IT FOR ME tweens the slider itself, so hand-scrub and autoplay share one source of truth.

3 · The wing lesson (pass 2)

The first design hinged "wings" on full-size inset elements; at 130° they rotated their invisible empty space too and flew off the table like shards. The fix is a rule worth keeping: a CSS-3D hinge must own small, locally-clipped geometry — a 26%-sized beak flap on its own crease stays inside the model. The last fold became "IT STANDS": tip the whole sheet upright, tighten its shadow — theatrical, and geometrically incapable of embarrassment.

4 · Diagrams in the real notation

Valley folds dashed, mountain folds solid, arrows in crane red — the four cards use actual origami conventions, and after pass 2 they describe the same four folds the sheet performs. Instructions that match the demonstration: rarer than it should be.

5 · The three passes

  1. Folds 1–2 verified; final state failed (wing shards).
  2. Contained beak + stand-up redesign; captions resynced to reality.
  3. Mobile stack + reduced-motion (slider jumps, no tween).
